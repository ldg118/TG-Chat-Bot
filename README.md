# TG Chat Bot

 [English](README_EN.md) | [中文](README.md)

基于 Cloudflare Workers 的 Telegram 消息转发机器人，集成防骚扰和反诈骗功能。

## 功能特点

- **无服务器架构**：运行在 Cloudflare Workers 上，低成本且高可用。
- **消息转发**：将用户发送给机器人的消息转发给管理员。
- **运行模式**：
  - **私聊模式**：一对一转发，轻量简单。
  - **话题群组模式**：为每个用户创建独立话题，多用户分房管理。
- **防骚扰与反诈骗**：
  - **关键词过滤**：自动丢弃包含黑名单关键词（如 '刷单', '兼职', 'USDT'）的消息。
  - **动态算术验证**：未验证用户需完成随机数学题（如 3+5=?）才允许发送媒体，有效拦截脚本攻击。
  - **自定义问答验证**：可维护 1~20 题的题库替代算术题，每次随机抽题，答案仅存服务端不泄露。
  - **多级安全策略**：支持严格（禁言）、标准（禁图）、宽松（免验证）三种安全级别动态切换。
  - **消息去重**：同一用户 2 分钟内的重复内容不会重复转发。
  - **屏蔽/信任系统**：支持屏蔽 (`/block`) 和永久信任 (`/trust`) 用户，屏蔽用户会收到一次解封提示。
- **管理功能**：
  - **全员广播**：回复一条消息即可全员广播（保留原格式/媒体，自动跳过黑名单）。
  - **可视化菜单**：提供 `/admin` 管理面板，分类导航+按钮点击执行。
  - **双语界面**：中/英文一键切换。
  - **多机器人**：一个 Worker 可挂多个机器人（共用 D1，数据按 bot 隔离），通过 `/bot` 指令管理。
  - **服务消息过滤**：自动忽略系统消息干扰。

### 环境变量

需要以下环境变量（在 Cloudflare Worker 的 Settings → Variables 中配置）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `BOT_TOKEN` | 是 | Telegram 机器人 Token（从 @BotFather 获取），建议设为 Secret |
| `ADMIN_UID` | 是 | 你的 Telegram 用户 ID（从 @userinfobot 获取） |
| `TOPIC_MODE` | 是 | `true` 开启话题群组模式，`false` 私聊模式（默认） |
| `SUPERGROUP_ID` | 话题模式必填 | 超级群组 ID（以 `-100` 开头） |
| `WEBHOOK_SECRET` | 否 | Webhook 安全校验字符串；留空则自动生成 UUID 存入 D1 |
| `MAX_MSG_PER_MIN` | 否 | 频率限制阈值（条/分钟），超限触发重新验证，默认 `40` |

### D1 数据库

创建一个 D1 数据库（如 `tgchatbot`），并在 Worker 的 Settings → Bindings 中添加 D1 绑定，**绑定名必须为 `D1`**。表结构在首次请求时自动创建，无需手动迁移。

### 注册 Webhook

部署完成后访问一次：`https://你的-worker-域名.workers.dev/registerWebhook?token=<你的BOT_TOKEN>`，返回 `Ok (default)` 即成功（`default` 是机器人 id）。

> ⚠️ **注册/注销端点需要 Bot Token 鉴权**：worker 域名是公开的，为防止陌生人访问 `/unRegisterWebhook` 导致消息接收瘫痪，`/registerWebhook` 与 `/unRegisterWebhook` 都必须带 `?token=<BOT_TOKEN>`（多机器人用对应机器人的 token）。缺失或错误返回 401。

Webhook 接收路径为 `/endpoint`（单机器人）；多机器人各用 `/endpoint/{id}`，对应注册入口 `/registerWebhook/{id}`。

## 运行模式

### 1. 私聊模式 (默认)
机器人直接将用户消息转发到管理员的私聊 (`ADMIN_UID`) 中。
- **设置**：只需配置 `BOT_TOKEN` 和 `ADMIN_UID`，`TOPIC_MODE` 留 `false`。
- **使用**：直接回复转发来的消息即可回复用户。

### 2. 话题群组模式 (推荐用于高并发)
机器人会在一个超级群组中为每个用户创建一个独立的 **Forum Topic (话题)**，井井有条地管理大量对话。

**设置步骤：**
1.  **环境变量**：
    - 设置 `TOPIC_MODE` 为 `true`。
    - 设置 `SUPERGROUP_ID` 为你的群组 ID (如 `-100xxxxxxx`)。

2.  **Telegram 群组设置**：
    - 创建一个新的群组（或使用现有群组）。
    - 将机器人拉入群组并设为**管理员**。
    - **关键**：机器人必须拥有 **"Manage Topics/管理话题"** 权限。
    - 在群设置中开启 **Topics (话题)** 功能：
      - 群组信息 -> 编辑 -> 话题 -> 开启。
      - *注：这会将群组转换为超级群组。*

3.  **获取群组 ID**：
    - 将 `@username_to_id_bot` 拉入群组，它会告诉你 ID。
    - 或者在网页版打开群组，URL 中包含 ID (例如 `#/-100123456789`)。

**注意**：话题由机器人自动创建并绑定用户。手动创建的话题机器人不认识，在里面发送的消息会被忽略；如需使用，回复一条该用户的转发消息即可自动完成绑定。

## 多机器人支持

一个 Worker（一份代码 + 一个 D1 库）可以同时挂多个机器人，**每个机器人的数据完全隔离**（黑名单、关键词、验证状态、消息映射、配置均按 bot 分开，互不影响）。

### 只有一个机器人？

**什么都不用配。** 直接使用环境变量 `BOT_TOKEN`、`ADMIN_UID` 等即可，系统把它当作 id 为 `default` 的机器人，webhook 路径为 `/endpoint`。

### 添加更多机器人（面板操作，免 Cloudflare）

在日常使用的管理面板（`/admin`）里用 `/bot` 指令即可，配置存入 D1 并**自动注册 webhook**：

```
/bot list                                         → 查看已添加的机器人
/bot add support 123:ABC 222222222                → 添加（id token 管理员UID）
/bot add vip 456:DEF 333333333 -100xxx topic 40   → 话题模式 + 自定义限流
/bot del support                                  → 删除并注销 webhook
/bot set support token 789:GHI                    → 修改字段（token/admin/sg/max）
```

**添加步骤：**

1. 从 @BotFather 新建一个 bot，拿到 token
2. 给 `default` 机器人发送 `/bot add <id> <token> <管理员UID>`（id 只能用小写字母/数字/`-`/`_`）
3. 完成。机器人会验证 token 有效性、注册 webhook、配置命令菜单

**参数说明：**

| 参数 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 机器人标识，决定 webhook 路径 `/endpoint/{id}` |
| `token` | 是 | 从 @BotFather 获取的 Bot Token |
| `管理员UID` | 是 | 该机器人的管理员 Telegram User ID |
| `sg` | 否 | 超级群组 ID（以 `-100` 开头），仅话题模式需要 |
| `topic` | 否 | 填 `topic` 则默认开启话题模式，否则私聊模式（可用 `/mode` 切换） |
| `max` | 否 | 频率限制（条/分钟），默认 `40` |

**注意点：**

- token 无效时不会保存；含 token 的消息会被自动删除防泄露
- 改了某个机器人的 `token`/`admin` 后，重新访问它的 `/registerWebhook/{id}?token=<该机器人token>` 生效
- `default` 机器人仍需手动访问一次 `/registerWebhook?token=<BOT_TOKEN>`

## 防骚扰功能详解

1.  **关键词黑名单**：
    - 命中可疑关键词（如"兼职"、"刷单"、"USDT"等）的消息会被静默丢弃。
    - 中文词按子串匹配；英文/数字词按**词边界**匹配（大小写不敏感），避免 `av` 这类短词误伤密码、账号等正常文本。
    - 默认 12 个词，通过 `/keyword` 指令增删。

2.  **验证体系**（三选一）：
    - **动态算术**（默认）：随机生成 `3 + 5 = ?` 类题目，点击选项按钮作答。运算类型、数值范围、选项数均可配置（默认 6 个选项）。
    - **自定义问答**：管理员维护题库（1~20 题），用户回复文本作答，每次验证随机抽一题。答案仅存服务端。
    - **关闭**：所有用户免验证。
    - **答错即换题**：答错后原地刷新为一道新题（题目与选项全部更换），累计答错 3 次需重新发消息触发。
    - 验证通过后 **1 小时**内免重复验证；发送频率超过 `MAX_MSG_PER_MIN` 条/分钟会要求重新验证。
    - 未验证时被拦截的消息会**暂存**，验证通过后自动补发。

3.  **多级安全策略**（仅对未验证用户生效）：
    - **严格 (1)**：未验证用户禁言。
    - **标准 (2)**：未验证用户可发纯文本，禁止发媒体（默认）。
    - **宽松 (3)**：无需验证。

4.  **屏蔽 (Shadowban 变体)**：
    - 管理员可以使用 `/block` 指令屏蔽用户，其消息不再被转发。
    - 被屏蔽用户会收到**一次**提示「你已被屏蔽，请联系管理员解封」，之后 **24 小时内静默**（不回复、不转发）。
    - 提示有节流（`BLOCK_HINT_COOLDOWN`），避免被刷接口；`/unblock` 会清除该记录，再次被屏蔽时可立即收到提示。

5.  **指令防滥用**：
    - 管理指令（`/admin`、`/bot`、`/help` 等）仅对管理员生效，陌生人发送时**不执行、也不转发到群组/话题**。
    - 陌生人会收到一条提示「该指令仅管理员可用，如需联系管理员请直接发送消息」；为避免被滥用刷接口，**同一用户 10 分钟内只提示一次**，其余静默忽略。
    - **命令菜单可见性可配置**（`/bot cmd all|admin|off`，或面板「🤖 机器人管理」内切换，按机器人独立生效、即时生效）：
      - `all`（默认）：所有私聊用户可见命令菜单；
      - `admin`：仅管理员私聊可见，陌生人输入 `/` 不再弹出管理命令；
      - `off`：对所有人关闭命令菜单（管理员仍可手输指令，面板按钮不受影响）。

## 管理员指令

发送 `/admin` 打开可视化控制面板（按钮点击即执行）：

- **/info**：查看用户信息（回复其消息或在其话题内发送）。
- **/trust** / **/untrust**：永久信任（跳过全部检查）/ 取消信任（同时清除信任附带的免验证状态）。
- **/block** / **/unblock**：屏蔽 / 解除屏蔽 。
  > 屏蔽、信任、清除等**破坏性指令必须显式指定目标**：回复该用户的消息，或在其话题内发送。面板按钮没有上下文时不会自动套用到"最近来信的人"，以免误伤（`/info` 只读，仍允许该回退）。
- **/blacklist**：查看黑名单列表。
- **/broadcast**：回复一条消息进行全员广播（自动跳过黑名单）。发送按约 25 条/秒节流，并在接近平台运行时限或触发 429 时**主动停止**并提示未送达人数，避免被中途掐断后结果失真；用户量大时可能需要分次广播。
- **/security <1|2|3>**：设置安全级别。
- **/verify <math|off|show>**：切换验证方式 / 查看配置。
- **/verify custom 问题 | 答案**：将题库设为唯一一题；**/verify add 问题 | 答案** 追加一题（上限 20）。
- **/verify list** / **/verify del 编号** / **/verify clear**：查看 / 删除 / 清空自定义题库（不回显答案）。
- **/math ops +-*/** / **/math range 1 9** / **/math count 4** / **/math show**：配置算术题库。
- **/keyword list|add 词|del 词|reset**：管理关键词黑名单。
- **/lang <zh|en>**：切换界面语言。
- **/welcome 文本**：自定义用户 `/start` 欢迎语（支持 `{uid}` 占位符）；`/welcome reset` 恢复默认。
- **/clear**：清除指定用户的消息映射与话题绑定（并重置接入信息卡）；`/clear all` 清空全部。
- **/mode <private|topic>**：切换运行模式。
- **/bot list|add|del|set**：管理多个机器人（存入 D1 并自动注册 webhook，免 Cloudflare 操作）。
- **/bot cmd <all|admin|off>**：命令菜单可见性（默认 `all`；`admin` 仅管理员可见；`off` 完全关闭），即时生效、按机器人独立。
- **/help**：查看全部指令说明。

### 权限系统说明 (/trust vs /block vs /unblock)

*   **`/block` (屏蔽/黑名单)**：加入黑名单并清除信任/验证状态；消息不再被转发，被打断的待验证状态与暂存消息一并清除。用户会收到一次「已被屏蔽」提示，之后 24 小时内静默。
*   **`/unblock` (解除屏蔽)**：仅移出黑名单，恢复普通状态（仍需按安全级别验证）。
*   **`/trust` (永久信任/白名单)**：跳过全部安全检查（免验证、免关键词、免去重），并自动解除屏蔽。优先级最高，与 block 互斥。

## 数据存储说明 (D1)

全部数据存储于 Cloudflare D1，表结构首次请求自动创建/修复：

- **user_states**：用户状态（屏蔽/信任/验证/频率/待答验证题/暂存消息/信息卡标记），永久保存。
- **message_mappings**：消息路由映射，主键 `(bot_id, admin_message_id)`，**永久保存**，通过 `/clear` 手动删除。
- **chat_topic_mappings**：用户 ↔ 话题双向映射，永久保存。
- **message_hashes**：内容去重哈希，按用户隔离，2 分钟有效期，过期后由每日 Cron 自动清理。
- **keywords**：关键词黑名单。
- **settings**：配置项（安全级别/验证模式/题库参数/语言/欢迎语/命令菜单可见性/webhook secret 等）。
- **bots**：多机器人配置（id/token/管理员/sg/模式/限流/secret），由 `/bot` 指令维护。

所有表均以 `bot_id` 作为主键首列，实现多机器人数据隔离。

**旧表自动清理**：冷启动时会比对当前代码使用的表清单，**不在清单内的表会被自动删除**（包括迁移中断残留的 `_old_*` 临时表）；`sqlite_` / `d1_` 前缀的系统表豁免。因此升级版本后废弃的历史表无需手动清理，也不要在同一个 D1 库里存放其他用途的表。

> 维护提示：新增数据表时必须同步加入代码顶部的 `TABLES` 白名单，否则会被当作废弃表删除。

**表结构版本号（性能相关）**：冷启动时先比对 `SCHEMA_VERSION`，版本一致则跳过全部建表/迁移探测（18 个查询降为 1 个）。**修改任何表结构后必须把 `SCHEMA_VERSION` 加 1**，否则新结构不会生效（表现为"代码更新了但表结构没变"）。

## 安装指南

1.  **获取 Token**：从 @BotFather 获取你的 Bot Token。
2.  **获取 UID**：从 @userinfobot 获取你的用户 ID。
3.  **创建 D1**：控制台 D1 中新建数据库（或 `wrangler d1 create tgchatbot`）。
4.  **部署**：点击上方的 "Deploy to Cloudflare Workers" 按钮，或在 Workers 控制台新建 Worker 后粘贴 `worker.js` 内容。
5.  **配置**：Settings → Variables 填入环境变量；Settings → Bindings 添加 D1 绑定（**绑定名 `D1`**）。
6.  **注册 Webhook**：访问 `https://你的域名.workers.dev/registerWebhook?token=<BOT_TOKEN>`。
7.  **（可选）Cron**：Triggers 中添加每日定时 `0 0 * * *`，用于清理过期去重哈希并重置过期的验证状态（不清除黑名单/信任等永久状态）。
